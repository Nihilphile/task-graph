# Task Graph 审查设计

状态：设计已确认（2026-09-28），已在 `codex/auto-review` 隔离工作区实现。本文保留设计依据；验证记录见 [交付说明](auto-review-delivery.md)，使用方式见 [独立审查](../../references/review.md)。现有安装入口尚未切换。

## 对话中已确认的方向

- 新增独立的 review-requirement 标签，允许多份验收要求；有有效材料才能开启 auto-review。
- task 可单独开启。graph 开启操作扫描任务，有 RR 的开启，没有 RR 的跳过。
- 交付后进入 pending_review。工具给审查者默认提示词及对应任务，让其按 RR 审查。
- 审查者通过 task-graph 登记报告和结果；有效 pass/reject 触发主控订阅通知。
- 执行器跟踪审查运行，退出但没有提交结果时警告主控。
- 提供 task[].review restart 恢复异常审查。

## 2026-09-28 补充确认

- 两条启动流程：auto-review 由主控开工前确定 RR，执行者完工后自动启动；manual review 由主控读完执行报告后确定 RR，通过 task[].review start 主动启动，不要求启用 auto-review。
- 不设工具级并发上限：任务交付后独立触发审查，不采用默认串行队列。外部服务的实际容量不由该约定保证。
- 默认审查模型为 GPT-6 Sol，推理强度 xhigh；允许自定义，review start --model 为用户提出的入口。CLI 实际模型标识与配置可用性实施时核验。
- 本版不纳入审查中撤回交付、修改 RR 的管理流程。此项不替代审查对象版本归属问题。
- 已完成任务手动 review start 后转为 pending_review，阻塞尚未开始的后继；已经执行中的后继继续运行，不自动停止或回滚。审查 reject 时通知主控问题及受影响后继，由主控处理。用户已明确认可。

## 执行与恢复约定

- 使用 codex exec 启动审查进程。普通 exec 支持非代码验收，不要求使用专门的代码 review 子命令。
- review finish 将报告快照、最终任务状态和通知事件一起保存。
- 每轮审查有唯一身份；重复提交幂等，过期结果拒绝回写。
- restart 沿用同一次提交的交付与 RR；修改交付或要求后重新提交。
- graph 操作为一次扫描，默认当前图，可显式递归；没有持续继承开关。
- 异常不自动重试，由主控选择 restart。

## 已确认的边界

### 审查对象与依据

记录本次交付版本，能隔离的检查按固定版本执行；Unity 等现场验证记录实际环境。RR 和任务要求使用本轮固定内容，报告须说明实际验证对象。重启使用相同对象；实现中需核验未提交文件也能被正确识别，不能只记录 HEAD 而忽略实际交付。

RR 和 content 中的明确任务约束共同作为验收依据。违反明确约束可以 reject；额外的风格、重构建议只记录，不阻塞通过。要求冲突或缺少足够判据时交主控处理。

### 审查结论

| 结论 | 任务状态 | 通知 |
| --- | --- | --- |
| pass | done | 本轮审查报告与通过结论 |
| reject | reject | 本轮审查报告、未通过原因及受影响后继 |
| blocked | pending_review | 本轮报告、缺失环境或材料、需要的介入 |

blocked 是审查者能够正常提交的结论；进程退出但没有 finish 是执行异常，单独记录并告警。二者都不自动判 reject。补齐环境后可用 review restart 重新审查。

### graph 扫描与任务覆盖

graph 开启执行一次扫描，有有效 RR 的任务开启，没有 RR 的跳过。已由主控显式关闭的任务保持关闭并列入跳过清单，主控可针对该任务重新开启。绑定失效、不可读或空文件须返回具体原因，不能算作有效 RR。

### 依赖与局部完成点

手动 review start 将已完成任务转为 pending_review；依赖该任务整体完成的后继在尚未开始时被阻塞，已开始的后继不自动停止或回滚。

部分依赖保持现有语义：只检查指定子任务的完成状态，父任务审查不会额外关闭已满足的局部完成点。某项局部能力需要审查时，在相应子任务启用审查；必须等待整体验收的后继声明依赖父任务。

### 并发与本版范围

不设工具级并发上限，不采用默认串行队列。同一任务仍需避免重复启动审查。默认 GPT-6 Sol / xhigh，支持自定义配置及 review start --model 覆盖。

本版不提供审查中撤回或修改要求的管理流程。自动审查在开工前确定 RR；手动审查在阅读执行报告后确定 RR。

## 实施时核验

以下属于工程验证，不重新打开已确认的产品决策：

- codex exec 的实际模型标识、配置传递、提示词 stdin、进程退出和会话标识。
- 固定交付的目录、未提交文件覆盖、现场环境记录与执行权限；不能把记录版本误当成已隔离版本。
- 配置保存位置、覆盖规则须在 CLI 帮助中明确，并在启动结果中返回本轮实际配置。
- 执行器重启后的运行状态核对、过期结果拒绝、通知事件去重与异常恢复。
- 完成入口、执行 claim 与审查身份的衔接，复合任务完成条件继续有效。

运行中的原目录与已安装 skill 不在本轮修改范围内。

## 核心验收场景

1. 多份 RR 能被登记、列出、读取并在 HTML 标签中查看；缺少有效 RR 时不能开启或手动启动审查。
2. graph 扫描区分开启、已开启、缺少材料、材料异常和显式关闭；重复扫描不重复启动进程。
3. 自动流程在执行者交付后进入 pending_review，不提前发送任务通过通知或放行完整依赖。
4. 未启用 auto-review 的已完成任务可手动 start；尚未开始的完整依赖阻塞，已运行后继与已满足的局部完成点不自动回滚。
5. pass/reject 提交保存本轮审查报告和结论后通知主控；blocked 保持 pending_review 并通知缺口。
6. 进程正常退出但未 finish、异常退出和启动失败均不能被当成通过，须有可定位的告警和日志。
7. finish 已保存后进程异常退出，不撤销有效验收结果；重复 finish 不重复生成结果通知。
8. 异常或 blocked 后 restart 创建新轮次，保留旧记录和固定验收对象；旧轮次迟到提交不能改写当前任务。
9. 多个任务分别触发审查，无默认并发上限；同一任务不会同时有两个有效审查运行。
10. 默认模型和推理配置可核实，显式覆盖实际传给执行器；不静默换用其他模型。
11. 报告可定位实际验收的交付与要求版本，额外建议不会单独造成 reject。
12. 未开启审查的原有任务流程保持兼容。

## 实施前的只读代码核查

- src/core/lifecycle.ts：当前 complete 直接进入 done/reject；执行领取只在终态释放。自动审查须调整完成入口，执行领取和审查身份分开记录。
- src/core/readiness.ts：完整依赖要求前置 done；部分依赖仅检查指定子任务，保留该语义。
- src/core/mutate.ts、watch.ts：通知目前只来自 done/reject 的历史事件；审查异常需要单独事件，结果需关联本轮报告，避免用最后几份普通报告代替。
- src/core/lock.ts、transaction.ts：已有短事务锁不能覆盖长时间审查；启动、回写分别短事务，codex exec 在锁外执行。现有多文件保存不提供数据库级断电原子性，需要恢复检查。
- src/core/documents.ts：报告可复用快照能力，新增轮次关联并处理重复 finish 的幂等性。
