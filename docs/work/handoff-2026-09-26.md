## 用户确认的职责边界

- to-task 面向写任务的主控：拆分、写 content、依赖、验收责任和交付约定。主控要知道 task-take 的协作行为，但无需在 to-task 重复执行者操作手册。
- task-take 面向接到已有 task 的执行者。start 返回指南路径；已由主控 start 或恢复时 show 取得指南。读取内容和必要参考、写简短接手记录后立即自主施工，无须主控二次许可。
- 同一次执行只由一方 start；主控代 start 时登记实际执行者会话 ID。已开始且未领取时可 claim；其他会话的领取须明确移交。
- 上下文缺口记工作记录：缺什么、影响什么、解除条件。可推进部分继续；确实无法继续时同时 block。日志/block 不主动唤醒主控，必要求助依赖调度环境。
- 完工结果放日志和附件，无须再让 worker 写重复的主控聊天回执。最终验收责任由任务写明，与接手后自主开工分开。

### Content 与 Reference

content 写规划时已知的目标、范围、约束、已确认接口与验收。reference 可以绑定既有资料，也承载施工后形成的实际代码入口、调用方式、限制及接入知识。

主控写清后继需要什么资料及用途、由哪个前置任务交付；不预测尚不存在的代码路径，也不把已知要求推迟给 reference。执行者按 task-take 在 complete 前登记必要 reference，优先绑定现有文件并给 summary，不足时写短接入说明。无实际需求不强制造文档。

reference 应反映实现；若偏离已确认约定，记录偏差和影响，由主控协调修订。reference 本身不构成改变任务约定的授权。
