# 任务上下文与派工检查

目标：接手者不依赖原主控的会话记忆，只用任务要求和明确引用，就能理解工作、定位资料、执行并验证。以下维度按任务需要覆盖，可以合并章节；不要求每项任务都有同样长的模板。

## 正文应回答的问题

| 维度 | 接手者需要知道什么 |
| --- | --- |
| 背景与目标 | 当前行为是什么，哪里不满足需要，本任务交付什么变化 |
| 范围与决定 | 修改范围、保留行为、已确定的方案及必要理由；哪些仍是待核实假设 |
| 协作接口 | 本任务提供或消费什么；输入输出、错误、副作用等必要约定在哪里；允许自主决定哪些内部细节 |
| 输入与前置产物 | 使用哪份需求、哪项前置交付的什么产物，怎样找到正确版本 |
| 工作入口 | 从哪个已核实的模块、符号、现有测试或脚本开始；必要工作目录与环境准备在哪里 |
| 验收 | 什么结果算完成，怎样复现和检查，由执行者还是主控验收并 complete；无法运行某项验证时应报告什么 |
| 交付 | 输出到什么位置或命名规则，报告应回答什么；后继需要哪些 reference、应包含什么及其用途 |

协议、格式、行为约定已经明确时引用其权威定义；缺少决定会让实现者互相猜测时，先解决或安排前置研究。不要把可变的内部实现细节全部固定成接口约束。

## 必读与按需资料

关键结论和短小必要背景写入正文。较长资料附精确定位，并区分：

- **必读**：开工必须掌握的约束、接口、验收、前置结论。
- **按需**：只有处理某个边界、定位问题或实现特定部分时才读取的资料。说明触发条件。

项目内文本定位默认相对项目根目录；可点击 Markdown 链接则按当前文件所在目录计算，保证 HTML 和仓库阅读时链接可用。

| 资料 | 有效定位示例 | 用途说明示例 |
| --- | --- | --- |
| 规格 | `doc/spec/export.md` → R-03、R-04 | 确认空结果和筛选快照语义 |
| 接口 | `src/export/contracts.ts` → `ExportRequest` | 确认生产者与消费者共用的字段；仅在已核实该文件/符号存在时使用 |
| 架构决定 | `doc/adr/007-export.md` →「兼容性」 | 继承既有 CSV 编码决定 |
| 外部结论 | 某一条 issue comment 的完整 URL | 读取最后确认的方案，而非让执行者翻遍讨论 |
| 前置产物 | 实际 task ID → report 分类 → 指定标题/路径、所需章节 | 找到已验收报告中的接口或迁移结论 |

行号可以辅助定位，最好同时给出符号、标题或唯一搜索词。依赖特定历史版本时注明 commit、文档版本或报告快照摘要；跟随当前代码的资料说明读取当前版本。

“按之前讨论”“参考相关代码”“见父任务”“参考报告”不足以定位必要结论。引用较大文档时指向相关章节，只有确实需要全篇理解时才要求读全文。

## 前置产物尚未生成时

content 承载主控已知的目标、范围、约束与验收；reference 可以绑定既有资料，也用于交付施工后形成的实现知识。例如“存储接口 → 页面接入”：页面 content 写清行为和已确认协议，存储任务的 reference 提供实际接口文件、调用示例与错误处理入口。主控无需预测尚不存在的代码路径，但应指明资料的产出任务及后继要用它解决什么问题。

写明产物应包含什么、由哪个前置任务交付、会以什么标题或路径绑定到该任务。关系写进 depends_on；同批创建可先用稳定 @key，批量返回后按实际 ID 查询。

在前置任务的交付要求中写清后继必需的 reference 内容与用途，例如接口定义、代码入口及错误处理约定。report 用于交付证据，handoff 用于同任务接续。执行者如何读取、登记参考及安排完成顺序，统一遵循 task-take。

前置任务完成后再核对产物是否满足消费条件。缺少必须的接口定义或证据时记录阻塞，即使前置状态是 done。reference 清单自动收集直接前置登记；命名完成点同时收集其父任务与 gate.requires 子任务的登记。报告等其他产物仍按实际 source_task 查询对应任务。无需把所有祖先材料装进当前上下文。

父任务的 content、主控聊天和日志不会自动完整继承给子任务。需要继承的结论在子任务中直接摘要或定位。不同任务可以引用同一份 spec、协议或共享背景文档；各自正文说明适用的部分。

## 对接手环境可读

派工信息提供项目/checkout 的实际位置、CLI 入口和 task ID。存在特殊运行方式时，在任务中提供已核实的启动或验证命令及执行目录；常规配置可定位到相关脚本。

引用只能在原主控机器访问的临时文件、私有会话或易失链接时，将必要结论保存到项目内的持久资料，或提供接手者可访问的位置。外部系统需要权限时说明访问前提，不把凭据写入任务。工具的 HTML 包含任务正文和受支持附件，但不会打包所有外部引用。

## 派工前的完成条件

逐任务查询当前清单，按需读取要求与必读引用，并遵守用途及项目路径排除，检查：

1. 能说明要实现什么、哪些行为必须保持，以及为什么有关键约束。
2. 能直接定位所需接口、代码入口和输入，不需要回读原聊天或重新寻找已得出的结论。
3. 能判断依赖产物是否可用，以及遇到缺口时由什么解除阻塞。
4. 能找到验证入口、判断完成，并提交约定的报告。

检查基于实际内容和引用可达性，不以章节齐全或字数达标替代。资料本身未解决的问题应显式保留；合理的代码探索与实现判断仍由执行者完成。

开始前发现必读引用失效或内容与任务约定冲突时，先核实当前权威版本并补充任务。中途交接则补记已做的事、证据位置和下一步，随后通过当前 task show 恢复；避免让旧 handoff 快照成为另一份最新要求。
