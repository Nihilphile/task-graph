# 任务上下文与派工检查

任务要求应让空白上下文执行者找到施工和验证依据；按任务需要覆盖以下内容，无须固定模板。

| 内容 | 要回答的问题 |
| --- | --- |
| 目标与范围 | 改变什么、保持什么，哪些决定已确认、哪些是假设 |
| 接口与前置 | 提供/消费什么约定，前置产物来自谁、如何定位 |
| 工作入口 | 已核实的模块、符号、测试、命令及特殊环境在哪里 |
| 验收与交付 | 完成条件、验证方法、审查责任、报告位置、后继必要 reference |

## 引用

区分必读约束与按需资料，后者写明读取条件。短结论可直接写入，长资料给路径及章节/符号；历史版本注明 commit 或快照，当前版本明确跟随 live。只引用已核实的文件，不用“参考前面讨论”代替定位。

正文中的路径相对项目根；Markdown 链接相对当前文件。资料须在接手环境可访问，易失或仅主控可见的结论保存到项目；外部访问说明权限前提，不写凭据。

父任务正文和聊天不会自动继承。共享约束绑定同一 [contract](../../../references/operations/contracts.md)，子任务只补本项范围和验收差异；正常内部实现细节留给执行者判断。

## 尚未生成的前置产物

后继要求写已知行为与约束，注明产出任务、产物标题/登记位置和用途，并建立 depends_on；同批建图可先用 @key。前置要求写明应实现的契约及必要入口，reference 按需登记已有代码，勿预测尚不存在的路径。

前置 done 后仍检查产物是否足以消费。代码条目从直接前置取得并按 ID 去重；gate 收集其父任务与 gate.requires 成员，其他材料按 source_task 查询，详见[上下文](../../../references/operations/context.md)。

## 派工检查

核对目标、必要引用、前置产物、验证入口和交付责任可定位。引用失效或冲突时先修正；未知保留为未知，不要求穷尽正常代码探索。并行安排见[主控协作](../../../references/workflows/controller.md)；执行与交接规则由 [task-take](../../task-take/SKILL.md) 维护，无须复制到任务正文。
