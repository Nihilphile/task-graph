# Matt Task Take

把已明确的工作做到可验证、可交接。沿用 Matt `implement` 的实现方法，由本技能统一执行流程；task-graph CLI 提供状态和材料操作，执行技能入口由派工方指定。无需再执行 `implement`、`implement-spec` 或 `task-take` 的工作流。

## 1. 接手并确定完成条件

读取用户指定的 spec 或任务要求、相关约定和必要前置证据。明确本次范围、可观察行为、测试 seam（验证行为的公开边界）以及交付位置。复用已有探索和确认；只针对影响范围、接口或验收的未决选择提问，其余在授权内自主处理。

收到 task-graph ID 时，先读 [CLI 接入与交接](references/task-graph.md)，取得 context、检查依赖和领取身份，再读取全部 content、绑定 contract 和 RR，以及接续所需报告。父任务正文和聊天不会自动继承。实际 checkout 与任务图项目位置分别确认。

只有 spec 或明确需求时直接实施，不为使用本技能额外建图。持有 review-id 时转到独立审查入口；本技能不兼任本轮 reviewer。任务拆分、依赖调整和共享约定的范围变化交由主控协调。

检查已有工作树修改，并记录本次基准 commit 和涉及范围，供审查区分已有工作与本任务改动。用户已指定基准时沿用该基准。

完成条件：要求、验证方法和执行身份足以施工；实际缺口有明确处理对象。

## 2. 实现与验证

行为改动优先在已约定 seam 做 TDD：先用一个失败测试观察目标行为，再做最小实现使其通过，逐条扩展。测试从公开接口验证行为，避免重算实现逻辑或依赖私有细节。已有 seam 决策直接继承；小型文案、配置或无行为变化的修改使用适合的检查，无须机械补测试。

采用 TDD 时读取已安装 `tdd` 的测试有效性与循环规则；需要详细测试或 mock 方法时再读取其相关参考。seam 确认按上一步已保存的约定处理。读取项目已有术语表、相关 ADR 和编码规则，使实现与项目语言一致。

实现过程中运行相关测试和类型检查；交付前运行适用的项目完整检查，已有有效结果可复用。失败则修复后重跑受影响检查。无法运行时记录具体原因与未验证范围。

仅为重要失败、阻塞或中途接续保留必要记录。遇到与已确认要求冲突的事项，暂停受影响部分、说明影响和所需决定，其余可独立工作继续。

完成条件：授权范围的行为已实现，验收条件有证据支持；不能证实的条件仍明确标为未完成或未验证。

## 3. 双轴审查并提交

整项工作收尾、进入最终审查与提交前，清理本轮产生且已被正式验证覆盖的临时 debug 脚本、重复测试和不提供有效行为证据的检查。保留能发现回归、验证约定或提供独立诊断信息的测试；若临时脚本仍是问题唯一可靠的复现方式，先整理为可维护的回归测试或诊断工具，再决定是否移除。清理限于本轮产物，保留他人已有材料；整理或删除影响测试执行时，重跑受影响检查。

按两个维度分别检查实际交付：

- **Standards**：项目明确的编码规则，以及命名、重复、耦合和多余抽象等可解释的维护问题。区分硬性违规与判断性建议。
- **Spec**：逐项检查任务要求是否缺失、部分实现、行为错误或超出范围；有 task-graph 时连同适用 contract 和 RR 检查。

需要代码异味判断细节时，读取已安装 `code-review` 的 Standards 基线作为参考。本阶段自行完成两轴检查，不附加原技能的 tracker 配置、固定询问或强制双代理流程。

审查覆盖本任务的已提交、暂存、未暂存和新文件。`git diff <base>...HEAD` 仅覆盖已提交部分；必要时分别检查 `git diff --cached`、`git diff` 和未跟踪文件。在共享工作树中限定本任务文件或代码块，不把他人的改动当成本次交付。非 Git 项目直接检查受影响文件及行为。

修复范围内的有效问题并验证；额外建议单列。按项目或派工已有约定，只提交本任务修改到当前分支，记录 SHA；未规定时使用项目惯例，无须另增固定提交格式。无文件变化时不做空提交。

完成条件：两轴均已检查，影响验收的问题已解决，交付版本可以定位。自行审查不能代替已配置的独立审查。

## 4. 轻量交接与交卷

有 task-graph 时按 [CLI 接入与交接](references/task-graph.md) 完成以下动作；无任务图时在最终回复中交代结果与验证，另存文件只在接续需要时进行。

- 写简短 report：最终结果、实际验证证据、交付 SHA 或版本位置、剩余限制。引用已有材料，避免复述实现过程。
- 后继需要定位重点代码时登记或更新 reference：路径、行号、符号和简短用途。按接续价值选择入口，无须逐文件登记。
- 实现改变已授权的共享契约时更新原 contract；超出约定的变化先协调。普通内部实现变化无需新建 contract。
- 正常完成通过 CLI `complete --report` 交卷，以回执判断 done 或 pending_review/reviewing。后两者表示已提交待审，结束本轮实现，后续修复按新派工接手。

中途交接才写 handoff，记录已做、未做、关键证据和下一步，并处理领取移交。未完成时保持真实状态。无需例行开工日志、逐步汇报或主控先批准 complete。

完成条件：交付证据已保存，必要入口可访问，CLI 返回成功且状态说明准确。若通知已由现有订阅处理，不重复发送；无自动通道且主控需要结果时，沿已有授权通道简短回报。

## 方法来源

改编自 Matt Pocock 的 [implement](https://github.com/mattpocock/skills/blob/main/skills/engineering/implement/SKILL.md)、TDD 和双轴审查方法，结合本地 task-graph 的领取、材料绑定与交付能力。本技能不负责创建或关闭外部 issue、发布 PR、整图调度或改变自动审查策略。
